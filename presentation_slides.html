01. 기획 배경 및 문제 정의

기존 복지 모델의 구조적 한계 극복을 위한 비접촉 다중 센서 융합 시스템 수립

권용석

기존 방식의 기술적/비용적 한계

  • 사회적 케어 인프라 부족: 수작업 전화 및 단순 방문 의존으로 독거 가구 폭증 대비 인력 공급의 물리적 한계.
  • 단순 규칙 감지기의 오작동: 단일 센서 임계값 비교 방식으로 인한 수많은 거짓 경보(False Alarm) 및 신뢰도 유실.
  • 정서 교감 메커니즘 부재: 감지 기능 중심 구성으로 피보호자의 고립 및 우울 해소를 돕는 물리적 교감 피드백 부재.

에지 AI 스마트 돌봄 솔루션

  • 비침습 다차원 센싱 데이터 융합: 사생활을 침해하는 카메라 관측 대신 온습도, 거리, 움직임, 조도를 종합 수집.
  • 에지 기계학습 모델 탑재: 저성장 라즈베리파이 상에서 실시간 일상 데이터 가공을 통해 고독/교감/안정 상태 추론.
  • 쌍방향 자율 피드백: 상황별 맞춤 행동(음성 콘텐츠 재생, 취침 유도, 감정 표현 모터 가동) 제공.

02. 하드웨어 아키텍처 및 정합 설계

전기적 레벨 시프팅 및 논리 제어를 통한 라즈베리파이 GPIO 안전 체계 구축

서석민

BCM 핀 매핑 및 전기적 인터페이스

컴포넌트 명칭 핀 번호 입출력 주요 역할 및 전기적 특징
DHT11 온습도 센서 BCM 12 Input 1-Wire 비트스트림 전송, 실내 적합도 산출용
HC-SR04 초음파 BCM 5, 6 Out/In 5V Level Shifter 적용 (100Ω/220Ω 전압 분배 회로)
PIR 모션 센서 BCM 21 Input 생활 움직임 반응 감지, 3.3V 출력 논리 다이렉트 맵핑
디지털 조도 센서 BCM 13 Input 소프트웨어 논리 반전 적용 (어두울 때 1, 밝을 때 0)
4채널 LED 출력 BCM 16, 20, 19, 26 Output 공통 음극(Common Cathode) 결선으로 와이어 최소화

레벨 시프팅 수식

5V (Sensor Echo Out)
└─ [ 100 Ω 저항 ] ─ GPIO Input Pin (3.43V)
└─ [ 220 Ω 저항 ] ─ Ground (GND)

V_in = 5V * 220 / (100 + 220) = 3.4375V
(3.3V 톨러런스 범위 이내 안전 통화)

03. 소프트웨어 및 온디바이스 AI 구조

FastAPI 비동기 스레드 파이프라인 및 경량화 TensorFlow Lite 추론엔진 최적화

서석민

비동기 병렬 스케줄링 (FastAPI)

  • asyncio 루프 백그라운드 구동: 메인 웹 응답 스레드를 블로킹하지 않고 센서 수집 및 AI 추론 루프를 1Hz 주기로 지속 가동.
  • 비동기 스레드 위임: 하드웨어 I/O 및 TFLite 추론과 같이 CPU 연산이나 파일 디스크립터 대기가 필요한 작업은 `asyncio.to_thread`를 사용하여 별도 격리 스레드풀로 전송.

경량 온디바이스 AI 추론엔진

  • tflite-runtime 최적화: 무거운 TensorFlow 풀 패키지 대신 에지 추론 전용 라이브러리로 메모리 및 기동 속도 개선.
  • 데이터 전처리: 온도, 습도, 거리, 생활 반응 센서 딕셔너리를 `(1, 4)` 차원의 float32 Numpy 배열로 인코딩하여 인터프리터에 주입.
  • 추론 클래스 사후 연산: 예측 소프트맥스 확률 분포 해석을 거쳐 안정(0), 교감(1), 이상위험(2) 상태 텍스트로 치환.

04. API 구조 및 학술 연구 기반 쾌적도 산정

실시간 웹소켓 연동 관제 체계 및 Thom의 불쾌지수 학술 공식 적용

권용석

실시간 및 제어 API 명세

  • GET `/` (View): Jinja2 HTML5 기반의 관리자 돌봄 모니터링 실시간 대시보드 반환.
  • WS `/ws` (Stream): TCP 웹소켓 파이프라인 개설을 통해 1Hz 주기로 센서 구조 데이터와 AI 상태를 JSON 브로드캐스팅.
  • GET `/api/record/start/{label}` (REST): AI 학습용 실버케어 상황 데이터 취합 수집 모드 가동 및 SQLite 영속성 로깅 활성화.
  • GET `/api/record/stop` (REST): 데이터 수집 루프 정지.

Thom의 불쾌지수(DI) 기반 쾌적도 산출

DI = 0.81 * T + 0.01 * H * (0.99 * T - 14.3) + 46.3
  • 최적 쾌적 구간 (60~68 DI): 인체 반응 최상의 구간으로 100점 만점 부여.
  • 고온 다습 구간 (DI > 68): DI 83(전원 불쾌) 기준 감점.
    Comfort Score = max(0, 100 - (DI - 68) * 6.67)
  • 저온 건조 구간 (DI < 60): DI 45(한랭 불쾌) 기준 감점.
    Comfort Score = max(0, 100 - (60 - DI) * 6.67)

05. 예외 격리 및 다중 폴백(Fallback) 메커니즘

하드웨어 지연 예외 처리 및 AI 핵심 객체 유실 대응 모니터링

서석민

하드웨어 및 소프트웨어 예외 복원력

  • 물리 I/O 지연 및 단선 대응: 센서 모듈 결선 유실 시 비동기 대기 블로킹 루프를 방어하기 위해 asyncio.wait_for 기반 2초 강제 타임아웃 격리 수행. 타임아웃 발생 즉시 기본 안전 대입 데이터(안전 거리 200cm 등)로 대체하여 프로세스 생존.
  • TFLite 모델 누락 및 로드 에러 대응: AI 모델 파일이 삭제되거나 훼손되어 로드 플래그(is_loaded)가 False가 되는 경우, 시스템은 룰 기반(Rule-based) 세이프가드 가동 모드로 자율 롤백하여 모션 및 거리 기준 자율 제어를 수행.

QA 가혹 시뮬레이션 결과

  • 시뮬레이터 가동 (`test_error.py`): 고의적 AI 인터프리터 해제(None) 및 5초 지연 블로킹 주입 가혹 조건 테스트 통과.
  • SLA 가용성 목표: 연간 가용성 99.9% 달성 설계 수립.

06. 에지 디바이스 무중단 배포 및 원격 관제망

Linux Systemd 데몬 서비스화와 Cloudflare Tunnel 보안 접속 기술 융합

공동 발표

Systemd 무중단 데몬 배포 [서석민]

  • 상시 가동 백그라운드 구현: SSH 연결 세션 이탈 시 강제 종료되는 스크립트 문제를 방지하기 위해 care_system.service 구성.
  • 자동 부팅 및 생존 관리: 라즈베리파이 시스템 부팅 시 자동 기동 및 데몬 크래시 발생 시 자동 재시작(Restart=on-failure) 파라미터 적용.

Cloudflare Tunnel 보안 관제 [권용석]

  • 포트포워딩 불필요: 복잡하고 해킹 위험에 직접 노출되는 공유기 외부 개방 없이 암호화된 아웃바운드 터널 생성.
  • 보안 HTTPS 접속 보장: cloudflared 데몬 연동을 통해 외부 모바일 기기 및 원격 복지사 망에서 안전한 대시보드 접근 및 관람 지원.
